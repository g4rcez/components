# Slider acceptance criteria

Verify these in the consuming application. They are test targets, not proof of WCAG conformance.

1. **Current behavior:** **Given** a number or an array and valid bounds and step, **when** a thumb is dragged or the track is pressed, **then** Base UI proposes a bounded numeric value through `onValueChange`. A controlled consumer that accepts it updates the thumb and the persistent value display. A number or a one-entry array renders one thumb, two entries render two, and no value renders one at `min`.
2. **Current behavior:** **Given** focus on a native range input in horizontal LTR mode, **when** arrows, Home/End, and Page Up/Page Down are used, **then** the value changes by `step`, reaches `min` or `max`, or changes by `largeStep` within the bounds. Keyboard steps never snap to marks.
3. **Current behavior:** **Given** a disabled slider with rendered thumbs, **when** pointer or keyboard adjustment is attempted, **then** the disabled native range inputs do not accept a value change, and neither the stretch nor a mark press changes anything.
4. **Current behavior:** **Given** `label`, **then** each thumb is named by it (a range as "label 1", "label 2"), and `formatValue` sets each thumb's `aria-valuetext`.
5. **Current behavior:** **Given** `marks`, **then** a tick is drawn for each mark inside the range at its percent position, the tick under the value is active, a value dragged or pressed within about 7px of a mark snaps to it, and `onValueChange` and `onValueCommitted` receive the snapped value.
6. **Current behavior:** **Given** labelled marks, **when** a label is pressed, **then** the nearest thumb moves to that value (a range stays ordered) and both callbacks run. Labels, icons and the value tag are hidden from assistive technology.
7. **Current behavior:** **Given** `tooltip`, **then** a value tag per thumb shows the formatted value on hover, focus and drag, and follows the value.
8. **Current behavior:** **Given** a horizontal, enabled slider and motion allowed, **when** a drag goes past either end, **then** the track stretches toward it by at most 36px and springs back on release; a key pushed against a limit nudges the track. With `elastic={false}`, a vertical slider, a disabled slider or reduced motion, there is no stretch and the value still reaches the end.
9. **Integration target:** **Given** a labeled two-thumb range, **when** each thumb is reached and adjusted, **then** focus stays visible, the permitted ordering and separation hold, and the shared name plus endpoint and value information is understandable.
10. **Integration target:** **Given** exact values or units matter, **when** any input method changes the value, **then** a persistent consumer display or a synchronized `Input` shows the accepted value; the tag is supplemental.
